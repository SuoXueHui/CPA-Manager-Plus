# 排查发现

- 同邮箱的多行是多个 OAuth 凭证，不是同一请求被重复写入。
- 合并金额应等于组内每份凭证按实际请求模型计算出的成本之和，不能除以凭证数量。
- `$102.49` 表示该账号组所有凭证的真实合计成本；逐凭证成本需要独立展示才能对账。
- 后端已经向 `credentials[].usage_windows` 返回请求数、Token 和 `cost_micro_usd`。
- 发布前复审发现旧逐凭证明细只渲染金额且可见值仅两位小数；两个 `$51.245000` 会各显示 `$51.24`，造成明细可见合计 `$102.48` 与账号合计 `$102.49` 不一致。
- 最小修复是在合并账号详情中按凭证显示数据库 ID、CPA Auth ID、状态、5h/7d 请求数、Token 和六位美元金额；账号行继续显示两位合计，不修改后端计价和账号容量逻辑。
- 当前生产 Manager 基线为 `cpa-manager-plus:refill-operating-stats-5b0caa6e-amd64`；本次只替换 Manager，Controller、CLIProxyAPI、数据库和认证文件不修改。
