# 认证文件时间排序任务计划

## 目标

为认证文件页面增加可持久化的“导入时间”和“最后请求时间”，并提供双向排序；原始请求日志清理或 CPA 重启后，已记录的时间仍然可用。

## 阶段

- [x] 阶段 1：梳理认证文件列表、Manager Server 存储、usage collector 和前端排序链路
- [ ] 阶段 2：以测试先行方式实现认证文件活动数据表及仓储接口（进行中）
- [ ] 阶段 3：接入认证文件发现和 usage event，持久化导入时间及最后请求时间
- [ ] 阶段 4：提供查询接口并在认证文件页面合并、展示和排序
- [ ] 阶段 5：执行后端、前端、构建和回归验证，检查文档同步

## 决策

- 不向认证 JSON 写入活动字段，避免 Token 文件频繁改写。
- 使用 Manager SQLite 独立活动表，避免 48 小时请求日志清理后丢失最后请求时间。
- 存量文件首次回填优先使用 CPA `created_at`，缺失时使用 `modtime/modified`，再缺失时使用首次观察时间。
- 最后请求时间统计成功和失败请求；“最久未使用”排序时从未请求的认证优先。

## 风险

- 存量文件缺少真实导入记录，只能做一次性近似回填。
- usage event 的 `auth_file_snapshot` 可能缺失，需要使用稳定认证身份字段进行兼容匹配。
- 当前工作区必须保持认证内容和管理密钥不进入日志、测试快照或提交。
